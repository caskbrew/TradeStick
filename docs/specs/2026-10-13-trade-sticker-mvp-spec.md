## 1. Цель и границы

### 1.1 Цель
Нативное macOS-приложение, в котором **каждая торговая сделка — отдельное окно-стикер на рабочем столе**. Пользователь вручную вносит транзакции (сколько монет и за сколько денег), а стикер показывает итоги сделки и прибыль/убыток в реальном времени по актуальной цене пары.

### 1.2 Что входит в MVP
- Приложение в menu bar без иконки в Dock.
- Создание сделки двух типов: **Buy-first** и **Sell-first**.
- Ручной ввод, редактирование и удаление транзакций.
- Расчёт итогов и PnL по определённой модели (раздел 5).
- Живая цена пары с биржи **Binance** через общий слой рыночных данных, спроектированный под добавление других бирж.
- Раскрывающийся список транзакций, плавно увеличивающий окно снизу.
- Сохранение всего между перезапусками.
- Локальная сборка и запуск.

### 1.3 Что НЕ входит в MVP
Реальные ордера, API-ключи и Keychain, балансы, Watchlist и Portfolio виджеты, комиссии, целевая цена (Target) и полоса Progress (убраны решением заказчика: стикер показывает только текущее состояние), stop-loss, мини-графики (sparkline), режимы отображения Minimal/Compact (макет, карточки 1–2, 4–5), иконки монет (используется монограмма), светлая тема, Futures/Margin, несколько аккаунтов, облачная синхронизация, экспорт CSV, уведомления, Launch at Login, автообновления, подпись Developer ID и нотаризация, локализация (кроме одного языка UI, см. 12).

### 1.4 Единственный пользователь
Разработчик. Это приложение для личного использования с открытым кодом; цель надёжность расчётов, а не масштабируемость.

## 2. Глоссарий

| Термин | Значение |
|---|---|
| **Instrument** | Торговая пара в нормализованном виде: `base` / `quote` (например GRAM / USDT). Не зависит от формата символа биржи. |
| **Exchange** | Идентификатор биржи (`binance`). Определяет источник цены. |
| **Trade (сделка)** | Одна логическая сделка = один стикер. Содержит Instrument, Exchange, Direction и список транзакций. |
| **Direction** | `buyFirst` — открывающая сторона BUY, закрывающая SELL. `sellFirst` — открывающая SELL, закрывающая BUY. Задаётся при создании. |
| **Opening side / Closing side** | Открывающая / закрывающая сторона транзакции относительно Direction. |
| **Transaction (транзакция)** | Запись: сторона (`buy`/`sell`), количество монет `qty`, сумма в quote-валюте `amount`, время. |
| **Rate** | Курс транзакции: `amount / qty`. В форме связан с Quantity и Amount (FR-TX-2): вводятся любые два из трёх. В хранилище не сохраняется. |
| **Open qty** | Количество монет, ещё не закрытых противоположными транзакциями. |
| **Last price** | Последняя известная цена пары с биржи. || **Quote asset** | Валюта, в которой измеряются суммы (USDT в основном сценарии). |

## 3. Пользовательские сценарии

| ID | Сценарий |
|---|---|
| S1 | **Создать сделку.** Меню → New Trade → выбор биржи, пары, Direction → появляется пустой стикер. |
| S2 | **Внести транзакцию.** В стикере: «Buy» или «Sell» → вводит количество монет и сумму USDT → Enter. Итоги и PnL пересчитываются сразу. |
| S3 | **Следить.** Стикер лежит поверх окон на всех рабочих столах, цена и PnL обновляются сами. |
| S4 | **Посмотреть историю.** Нажимает на стрелку, окно увеличивается, видны введённые транзакции. |
| S5 | **Исправить ошибку.** Редактирует или удаляет транзакцию в списке, итоги пересчитываются. |
| S6 | **Закрыть сделку.** Остаток доходит до нуля, стикер получает статус Closed и остаётся с итоговой прибылью. |
| S7 | **Перезапуск.** После перезапуска или перезагрузки все видимые стикеры возвращаются на те же места с теми же данными. |
| S8 | **Скрыть / вернуть.** Закрывает окно крестиком (сделка остаётся), позже открывает из меню. |
| S9 | **Удалить сделку** целиком, с подтверждением. |
| S10 | **Несколько сделок.** Несколько стикеров, в том числе по одной паре, работают независимо. |
| S11 | **Нет сети.** Приложение показывает последнюю цену с явной пометкой; ввод транзакций продолжает работать. |

### 4.2 Создание сделки (FR-NEW)

| ID | Требование |
|---|---|
| FR-NEW-1 | Диалог создания содержит: **Exchange** (выпадающий список зарегистрированных бирж; в MVP единственный пункт Binance), **Pair** (поле ввода `BASE/QUOTE`, например `GRAM/USDT`), **Direction** (Buy-first / Sell-first; переключатель с пояснением каждого варианта). |
| FR-NEW-2 | Пара проверяется через адаптер выбранной биржи: она должна существовать и быть доступной для spot-торговли. При ошибке показывается понятное сообщение и сделка не создаётся. [V: см. 11, листинг GRAM/USDT на Binance] |
| FR-NEW-3 | Регистр и разделитель вводятся свободно (`gram/usdt`, `GRAMUSDT`, `GRAM-USDT`); приложение приводит к каноническому виду. Неоднозначный ввод без разделителя разрешается через список пар биржи. |
| FR-NEW-4 | После создания открывается стикер в пустом состоянии, поле ввода первой транзакции активно. |
| FR-NEW-5 | Можно создать любое число сделок, в том числе несколько по одной паре. |
| FR-NEW-6 | Direction и Pair **нельзя менять** после создания первой транзакции. Биржу можно менять (см. FR-EX-4). |

### 4.4 Содержимое стикера (FR-UI)

Единый фиксированный макет (по `docs/ref002.png`, карточка 3 «Detailed», без графика). Режимов Minimal/Compact нет. Сверху вниз:

1. **Заголовок:** монограмма монеты (цветной круг с буквой, цвет от названия монеты), `BASE/QUOTE`; подпись `BUY · Spot · Binance` и бейдж статуса (`EMPTY` / `OPEN` / `CLOSED`); справа меню `⋯`.
2. **Текущая цена** (крупно) и изменение за 24 ч в процентах (FR-PRICE-10), индикатор свежести (4.6).
3. **Блок цифр** (две колонки):
   - слева: **Entry (avg)** (цена входа открытой части), **Amount** (открытое количество монет);
   - справа, крупно: **Total PnL** (сумма в quote-валюте со знаком) и **PnL %**; Цвет зелёный/красный/нейтральный **плюс** знак `+`/`−` и стрелка `▲`/`▼`.
4. **Итоги по сторонам** (мелкий шрифт, **две строки одна под другой**, первой строка открывающей стороны): `Bought qty @ avg buy rate`, `Sold qty @ avg sell rate`.
5. **Кнопки** зависят от Direction (FR-TX-1a) и стрелка раскрытия списка с числом транзакций.

Раскрытый список транзакций добавляется **ниже** этого блока (4.5); блок 1–5 остаётся неизменным.

### 4.5 Транзакции и список (FR-TX)

| ID | Требование |
|---|---|
| FR-TX-1 | **Форма ввода** (встроена в стикер, открывается кнопкой действия, FR-TX-1a): сторона (задана кнопкой, можно переключить), **Quantity** (монет), **Amount** (в quote-валюте, например USDT), **Rate** (курс; связь полей в FR-TX-2), **Time** (по умолчанию «сейчас», можно изменить). |
| FR-TX-1a | **Кнопки действий** (решение заказчика): одна кнопка **Add transaction** (открывает форму, по умолчанию с открывающей стороной; сторону можно переключить в форме) и, пока `openQty > 0`, кнопка **Close**. Ордера не отправляются. **Close** предзаполняет форму закрывающей транзакцией на весь `openQty` по текущей цене (оба поля редактируются). Кнопок `Buy more`/`Sell part`/`Buy back` нет. |
| FR-TX-2 | **Три связанных поля: Quantity (Q), Amount (A), Rate (R), всегда `R = A / Q`.** Quantity всегда вводится пользователем и сама не вычисляется. Из двух остальных (Amount и Rate) **вводом считается то, которое изменено последним**, другое вычисляется на лету (ввёл Q и A → R вычисляется; затем исправил R → вычисляется A). Вычисляемое поле выглядит приглушённо (подпись `auto`) и становится вводом, как только пользователь начинает его редактировать. Пока Q пуста или равна нулю, вычисляемое поле пусто. |
| FR-TX-2a | **Что сохраняется:** только Quantity и Amount. Если вводом является Rate, то `A = Q × R`, округляется до 8 знаков после запятой (точность quote-валюты, [A]) и сохраняется; отображаемый затем Rate = `A / Q` может чуть отличаться от введённого (в пределах округления A). Деление на ноль и нулевые/пустые значения не допускаются (FR-TX-3). |
| FR-TX-3 | Валидация: Quantity > 0, Amount > 0, десятичный разделитель `.` или `,`, пробелы-разделители тысяч допускаются, отрицательные и нечисловые значения отклоняются, время не позже «сейчас + 1 минута». |
| FR-TX-4 | **Проверка согласованности:** добавление, правка и удаление транзакции отклоняются, если в итоговой хронологической последовательности закрывающие транзакции когда-либо превысят накопленный открытый объём (см. 5.4). Сообщение указывает, на какой транзакции нарушение. |
| FR-TX-5 | **Список** показывается при раскрытии и содержит колонки: время, сторона (BUY/SELL, не только цвет), Quantity, Amount, Rate. Отсортирован по времени (новые сверху); при равном времени по порядку создания. |
| FR-TX-6 | Каждую транзакцию можно **редактировать** (те же поля, та же валидация) и **удалять** (с подтверждением, кроме случая, когда удаление последней свежесозданной транзакции совершается в течение нескольких секунд после ввода: тогда достаточно Undo, если успеем в MVP; иначе всегда подтверждение) [D: всегда подтверждение]. |
| FR-TX-7 | Высота списка: до 8 строк видны, дальше прокрутка. |
| FR-TX-8 | Список раскрывается **плавно снизу, как выпадающий** (анимация ≈0,2 с; при включённом «Уменьшить движение» без анимации): окно увеличивается вниз, верхний край и горизонтальное положение сохраняются. ## 5. Расчётная модель

Единственный источник истины — список транзакций. Все показатели — чистые функции от него и от текущей цены `P`.

### 5.1 Определения
Для сделки с Direction `D`:
- Opening side `O` = BUY для `buyFirst`, SELL для `sellFirst`; Closing side `C` — противоположная.
- Транзакции обрабатываются в хронологическом порядке (время, затем порядок создания).

### 5.2 Состояние метода средней стоимости (average cost)
Хранятся `openQty` и `openCost` (сумма в quote-валюте, приходящаяся на открытую часть). Начально оба 0, `realized = 0`.

- **Открывающая** транзакция (`qty`, `amount`): `openQty += qty`, `openCost += amount`.
- **Закрывающая** транзакция (`qty`, `amount`):
  - требуется `qty ≤ openQty`, иначе транзакция недопустима (см. 5.4)
  - `avg = openCost / openQty`
  - `closedCost = avg × qty`
  - для `buyFirst`: `realized += amount − closedCost`
  - для `sellFirst`: `realized += closedCost − amount`
  - `openQty −= qty`, `openCost −= closedCost`

### 5.3 Показатели

| Показатель | Формула |
|---|---|
| Bought qty / amount | суммы `qty` / `amount` всех BUY |
| Sold qty / amount | суммы `qty` / `amount` всех SELL |
| Avg buy rate | `Bought amount / Bought qty` (если Bought qty > 0) |
| Avg sell rate | `Sold amount / Sold qty` (если Sold qty > 0) |
| Open qty | `openQty` |
| Entry price (цена входа открытой части) | `openCost / openQty` (если openQty > 0) |
| Realized PnL | `realized` |
| Unrealized PnL, `buyFirst` | `openQty × P − openCost` |
| Unrealized PnL, `sellFirst` | `openCost − openQty × P` |
| Unrealized, если цена неизвестна | не определено (показывается прочерк), Total тоже не определён, но Realized показывается |
| Total PnL | `realized + unrealized` |
| PnL % | `Total PnL / Σ amount всех открывающих транзакций` (если Σ > 0) |
| Status | `EMPTY` — нет транзакций; `OPEN` — `openQty > 0`; `CLOSED` — есть транзакции и `openQty = 0` |
Статус вычисляемый: добавление транзакции в закрытую сделку автоматически возвращает её в `OPEN`.

### 5.4 Инвариант допустимости
В любой момент хронологической последовательности `openQty ≥ 0`. Любая операция (добавление, правка, удаление), нарушающая это, **отклоняется** целиком с указанием первой нарушающей транзакции. Это обеспечивает, что нельзя продать больше купленного (buy-first) и откупить больше проданного (sell-first), в том числе при вводе задним числом.

### 5.5 Примеры для проверки (используются как тесты)

**Пример A: buy-first, GRAM/USDT**

| # | Сторона | Qty | Amount | Rate |
|---|---|---|---|---|
| 1 | BUY | 1000 | 50 | 0.05 |
| 2 | BUY | 500 | 30 | 0.06 |
| 3 | SELL | 600 | 40 | 0.0666… |

- После 1–2: openQty 1500, openCost 80, entry 0.05333…
- Транзакция 3: avg = 80/1500, closedCost = 32, **realized = 40 − 32 = +8**, openQty 900, openCost 48.
- При `P = 0.055`: unrealized = 900×0.055 − 48 = **+1.5**; total = **+9.5**; PnL % = 9.5 / 80 = **11.875 %**.
- Avg buy = 80/1500 = 0.05333…; Avg sell = 40/600 = 0.06666….

**Пример B: sell-first**

| # | Сторона | Qty | Amount |
|---|---|---|---|
| 1 | SELL | 1000 | 60 |
| 2 | SELL | 1000 | 50 |
| 3 | BUY | 500 | 20 |

- После 1–2: openQty 2000, openCost 110, avg 0.055.
- Транзакция 3: closedCost = 27.5, **realized = 27.5 − 20 = +7.5**, openQty 1500, openCost 82.5.
- При `P = 0.058`: unrealized = 82.5 − 1500×0.058 = **−4.5**; total = **+3.0**; PnL % = 3 / 110 = **2.727 %**.

**Пример C: закрытие.** В примере A добавить SELL 900 за 54: realized += 54 − 48 = +6, итого realized = **+14**, openQty 0, статус **CLOSED**, итоговый PnL **+14**, PnL % = 14/80 = **17.5 %**.

**Пример D: недопустимо.** В примере A попытка добавить SELL 1600: отклонено (превышает openQty 1500 на момент).

## 7. Архитектура (кратко, для ТЗ)

Единый локальный SwiftPM-пакет + приложение. Зависимости направлены вниз.

```
App (menu bar, StickerPanel, WindowRegistry)
 └─ Widgets (TradeStickies view + view model, @MainActor)
     └─ MarketData (actor MarketDataHub: refcount, snapshot/stream, freshness)
         └─ ExchangeAdapter (protocol)  ←  BinanceAdapter
Domain (Instrument, Transaction, Trade, PnL calculator, Decimal) — без зависимостей
Persistence (SQLite) — зависит от Domain
```

Ключевые решения:
- **Domain чистый:** калькулятор PnL — чистая функция `([Transaction], Direction, price?) → TradeSummary` или ошибка инварианта.
- **Одна подписка на (биржа, пара)** через `MarketDataHub`; окна получают поток значений, UI дросселируется.
- **Окна:** один `NSPanel`-подкласс на сделку, содержимое на SwiftUI. Реестр окон по `Trade.id`.
- **Хранилище:** SQLite (GRDB предпочтительно, [V] окончательный выбор после сравнения с SwiftData; критерий: контроль над миграциями и Swift 6).
- Без DI-фреймворков и лишних абстракций.

## 8. Жизненный цикл и состояния

### 8.1 Сделка
`EMPTY` → (добавили транзакцию) → `OPEN` → (openQty = 0) → `CLOSED` → (добавили открывающую транзакцию или удалили/правка закрывающей) → `OPEN`. Статус не хранится, а выводится.

### 8.2 Окно
`Visible` ⇄ `Hidden` (по крестику / из меню). Сделка вне окна продолжает существовать. Удаление сделки уничтожает и окно.

### 8.3 Подписка на цену
Подписка активна ⇔ окно видимо **и** статус `OPEN` или `EMPTY`. (Для `EMPTY` цена нужна, чтобы подсказать курс при вводе.) При переходе в `CLOSED` подписка снимается, при возврате в `OPEN` восстанавливается.

## 14. Результаты проверки согласованности

| # | Найдено | Решение |
|---|---|---|
| C1 | «Средний rate» неоднозначен при наличии покупок и продаж. | Показываем три значения: avg buy, avg sell, цена входа открытой части (5.3). |
| C2 | При частичном закрытии нужно правило себестоимости. | Average cost: цена входа остатка не меняется при закрытии (5.2). |
| C3 | Sell-first на споте не является шортом. | Это обратный порядок round trip; приложение не проверяет наличие монет у пользователя и не моделирует займ (допущение). |
| C4 | Ввод задним числом может создать «отрицательную» позицию. | Инвариант 5.4, проверка при добавлении, правке и удалении. |
| C5 | «Closed» и возможность дальше добавлять транзакции. | Статус вычисляемый и обратимый. |
| C6 | Закрытие окна и удаление сделки — разные действия. | FR-APP-4, S8, S9. |
| C7 | «Подписка на цену» для скрытых и закрытых окон расходует ресурсы без пользы. | Подписка только у видимых `OPEN/EMPTY` (8.3). |
| C8 | Малоликвидная пара и stale-индикация могут выглядеть как сбой. | FR-PRICE-4. |
| C9 | «Выпадающий список увеличивает окно» конфликтует с ручным изменением размера и краем экрана. | Ручное изменение размера отсутствует; рост вниз со сдвигом вверх на краю (FR-WIN-5, FR-TX-8). |
| C16 | Макет показывает уголок изменения размера и три размера карточки; заказчик: размер меняется только при показе списка. | Один фиксированный макет, уголка нет (FR-WIN-5). |
| C17 | Макет показывает `SHORT · Spot`; заказчик выбрал термины Buy-first / Sell-first. | В интерфейсе `BUY-FIRST`/`SELL-FIRST`; кнопки `Sell more`/`Buy back` вместо `Add short`/`Buy to close`. |
| C18 | Макет не показывает суммарные Bought/Sold и их средние курсы, а исходное требование их требует. | Добавлена строка «Итоги по сторонам» в основной блок (4.4, п. 5). Нужно подтверждение, что это не перегружает вид. |
| C19 | Target и Progress на референсах исключены заказчиком («только текущее состояние»). | Удалены из требований, модели хранения, формул и приёмки (v0.3). |
| C20 | Макет содержит графики, иконки монет, светлую тему не показывает. | Графики и иконки монет вне MVP (монограмма), только тёмное оформление. |
| C22 | Референсы `ref-dashboard-001/002/003` используют зелёный и красный для `OPEN`, направления и `Close`, что противоречит семантике «зелёный/красный = плюс/минус». | FR-UI-8: нейтральные цвета для статуса, направления и `Close`. |
| C23 | В `ref-dashboard-001` у B счётчик «4 transactions» при трёх транзакциях, у C `Sell part` неактивна, а 24 ч совпадает с PnL %; в `-001/-002` монограмма меняет цвет между карточками. | Эти детали считаются ошибками референса; верные правила в FR-UI-7…14 и FR-TX-1a. |
| C24 | Референсы показывают Rate редактируемым, а ТЗ хранило только Q и A. | Три связанных поля, вводятся любые два; хранятся Q и A (FR-TX-2/2a). Округление при выводе A или Q из Rate документировано. |
| C25 | На референсах Rate в форме `500 / 30.00` равен `0.05000`, правильно `0.06000` (только `GRAM_USDT Trading Dashboard UI Showcase-3` верен). | Ошибка референса; значение пересчитывается по `R = A / Q`. |
| C26 | Ошибки референсов: в `Collage-4` у B `Sold 2,000 @ 0.05300` (верно `0.05500`); в `Dashboard-5` у C «1 transactions»; в `пять карточек GRAM_USDT-2` у `Live` стрелка-меню; в `Montage-1` формы показаны отдельными мини-карточками с заголовком, а в стале цена не приглушена. | Верные правила: FR-UI-15…18. |
| C27 | Спайк M0 показал: у окна нет «домашнего» Space (после смены его нельзя вернуть программно), Pin на «все Spaces» застревает в полноэкранном Space, нет главного меню без Dock-значка (Cmd+W не работает). | Pin, Stationary и Cmd+W убраны; окно живёт на одном Space как заметка (FR-WIN-2, FR-WIN-9, FR-WIN-10, FR-APP-4). |
| C28 | При реализации стикера заказчик убрал Realized/Unrealized, `Buy more`/`Sell part`, поставил итоги Bought/Sold друг под другом и цвета BUY/SELL в списке. Значения, округляющиеся до нуля, не должны получать знак и цвет. | FR-UI-3/4/8/16, FR-TX-1a; знак и цвет определяются по отображаемому, а не по точному значению (`NumberFormat.displayedQuote`). |
| C21 | Кнопка `Close` на макете в реальном приложении отправляет ордер. | В MVP только предзаполненная форма транзакции, ордера не отправляются (FR-TX-1a). |
| C10 | Смена биржи в сделке: пара может не существовать на новой бирже. | FR-EX-4: смена разрешена только при существовании пары; транзакции независимы от биржи. |
| C11 | Сумма в quote-валюте и PnL предполагают одну валюту. | Все суммы сделки в quote-валюте её пары; смешение валют невозможно по конструкции. |
| C12 | Отображаемые округлённые числа могут «не сходиться». | FR-FMT-1, FR-FMT-6: расчёт точный, итоги не суммируются из округлённых. |
| C13 | `c` в miniTicker — «Close price» 24ч-окна, а не «последняя сделка». | [A]/[V] R4. |
| C14 | Ввод текста в non-activating панели может не работать. | [V] в M0; запасной вариант: панель становится key-окном только на время ввода. |
| C15 | Комиссии не учитываются, но реальный PnL от них зависит. | Явно вне MVP; в UI подпись «без учёта комиссий». |
